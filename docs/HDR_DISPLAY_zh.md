# HDR显示与亮度映射说明

本文说明EyeQ播放HDR内容时，亮度经过哪些映射、由哪些选项决定，以及在macOS桌面和DeckLink监视器上分别会发生什么。

## 1. 整体链路

```
源（PQ / HLG / SDR，可带静态或动态元数据）
  │  ① EyeQ映射：每个源各自映射到同一个映射目标；没有映射目标时不映射
  ▼
公共结果（所有视频在同一亮度空间内对比、切换、滑动）
  │  编码为输出信号（PQ或SDR）
  ├─► macOS桌面窗口 ──② 系统映射（EDR）──► 显示器
  └─► DeckLink输出 ─────────────────────► 监视器（③ 监视器自身处理）
```

- ①由EyeQ完成，由`--target-display-nits`和`--tone-mapping`决定（第3节）。公共结果的尺寸固定（Fill/Slide为主视频分辨率，Grid为窗口像素尺寸）；编码后再按窗口或DeckLink模式的尺寸等比缩放并加黑边，缩放在输出编码域（如PQ码值）里进行，使用`--scale-method`。桌面窗口和DeckLink显示同一画面。
- ②只在macOS桌面输出PQ时存在，由系统完成。EyeQ无法控制它，只能通过交给系统的HDR元数据影响它（第4.3节）。SDR输出是普通图层，系统不做亮度映射。
- ③取决于监视器：专业参考监视器通常按绝对亮度显示PQ，超过面板峰值的部分截断；消费级电视可能自行做tone mapping。

术语：

| 术语 | 含义 |
|---|---|
| PQ | HDR10使用的传输函数（SMPTE ST 2084），码值对应0–10000 nits的绝对亮度 |
| 母版峰值 | 源的mastering display元数据中的最大亮度，如1000或4000 nits |
| MaxCLL | 内容中最亮像素的亮度。可以略高于母版峰值；EyeQ的映射不使用它，只把它原样交给macOS |
| 映射目标 | EyeQ把所有源统一映射到的显示条件：峰值为N的HDR显示，或SDR显示 |
| EDR余量 | macOS允许HDR最亮达到SDR白的多少倍。随亮度设置、预设和是否有HDR内容变化 |
| 参考模式 | Apple XDR显示器的参考预设，如“HDR Video (P3-ST 2084)”，SDR白和峰值都固定 |

## 2. 怎么选

| 目的 | 推荐设置 |
|---|---|
| 日常浏览，希望与QuickTime观感一致 | 不指定映射目标 |
| 主观质量评估、绝对亮度判断 | 参考模式 + `--target-display-nits 1000` |
| 需要可复现的渲染帧，或跨机器一致 | 指定映射目标 |
| 在SDR显示器上由EyeQ决定HDR如何映射 | `--target-display-nits sdr` |
| 模拟参考监视器超出峰值即截断 | `--target-display-nits N --tone-mapping clip`或`clip-rgb` |

不指定映射目标时，EyeQ不压缩源，显示效果完全依赖系统映射，会随亮度设置和显示器变化。指定映射目标时，EyeQ的映射与机器、显示器设置无关，同一命令得到相同的Ctrl+E渲染帧。

## 3. 选项与规则

使用者只需要回答两个问题：**映射到哪里**（`--target-display-nits`）；**怎么映射**（`--tone-mapping`）。

### 3.1 映射到哪里：`--target-display-nits <nits|sdr>`

| 取值 | 含义 | 输出 |
|---|---|---|
| 不指定 | 没有映射目标，EyeQ不映射 | 随主视频：主视频为HDR时输出PQ，为SDR时输出SDR |
| `N` | 峰值为N nits的HDR显示 | PQ |
| `sdr` | SDR显示，映射目标峰值为SDR白（`--reference-white`，默认203 nits） | SDR |

没有默认值。输出是PQ还是SDR，由映射目标（没有时由主视频）决定，**不由显示器决定**：在SDR显示器上播放PQ主视频时，EyeQ仍输出PQ，由macOS映射到SDR，EyeQ会给出警告。

输出色彩空间（桌面窗口和DeckLink相同）：

| 映射目标 | 输出色彩空间 |
|---|---|
| 不指定 | 与主视频相同，例如BT.709 / BT.1886、BT.2020 / PQ、BT.2020 / HLG；没有色彩标签时按BT.709 / BT.1886 |
| `N` | BT.2020 / PQ |
| `sdr` | BT.709 / BT.1886；主视频为sRGB时为BT.709 / sRGB |

- `sdr`的色域固定为BT.709：主视频是宽色域SDR（例如P3）时，超出BT.709的颜色会被截断。需要保留宽色域时，不指定映射目标即可。
- 不指定映射目标而主视频的传输函数EyeQ不能输出（例如gamma 2.2）时，EyeQ报错并提示指定映射目标。
- 系统没有提供所需的窗口格式时（例如macOS没有P3 / BT.1886窗口），EyeQ改用窗口实际的色域，并在日志中说明。

### 3.2 怎么映射：`--tone-mapping {system,clip,clip-rgb,spline}`

只处理超出映射目标的部分；源峰值不超过目标时，四种方式结果相同。

| 取值 | 含义 |
|---|---|
| `system` | EyeQ不映射，交给系统，与QuickTime的做法一致。不指定映射目标时的默认值 |
| `spline` | 压缩高光，保留高光层次。指定了映射目标时的默认值 |
| `clip` | 截断并保持色调：超出的像素按最大通道等比缩小到目标峰值，整体变暗 |
| `clip-rgb` | R、G、B各自截断到目标峰值，超出的颜色会偏白或偏色 |

例如映射目标为300 nits时，源像素(626, 513, 347)经`clip`变为(300, 247, 167)，经`clip-rgb`变为(300, 300, 300)。`clip`和`clip-rgb`都不改动范围内的像素。

映射目标为`sdr`时，`clip`在BT.2020中等比缩小，转到输出色域时，超出色域的饱和色仍会被逐通道截断。

启用了动态元数据自带映射的源不受`--tone-mapping`影响，目前只有`--hdrvivid-render`下的HDR Vivid（第8节）。

### 3.3 两个选项的组合

| `--target-display-nits` | `--tone-mapping` | 结果 |
|---|---|---|
| 未指定 | 未指定或`system` | EyeQ不映射，输出随主视频 |
| 未指定 | `clip` / `clip-rgb` / `spline` | 报错：缺少映射目标 |
| `N`或`sdr` | 未指定 | 按`spline`映射到目标 |
| `N`或`sdr` | `clip` / `clip-rgb` / `spline` | 按指定方式映射到目标 |
| `N`或`sdr` | `system` | 报错：冲突 |

### 3.4 必须指定映射目标的情况

EyeQ不替使用者选择映射目标。下列情况不指定就报错退出：

| 情况 | 需要 |
|---|---|
| 主视频为SDR，同时有HDR视频 | `sdr`（输出SDR）或`N`（输出PQ，SDR视频按参考白放入） |
| `--monitor-device` | `N`（PQ监视器的峰值）或`sdr`（SDR监视器） |
| `--hdrvivid-render` | `N`或`sdr`，作为Vivid曲线的目标显示亮度 |

其他冲突：

- `--monitor-color`显式指定的值必须与映射目标一致：`pq2020`配`N`，`sdr709`配`sdr`。
- 请求了PQ输出而平台不提供HDR窗口格式时，EyeQ报错退出，并提示改用`--target-display-nits sdr`，不会静默截断。

## 4. macOS桌面

本节只涉及PQ输出。不同显示器的EDR余量、预设和系统映射可能不同。

### 4.1 参考模式：系统按绝对亮度显示

切到“HDR Video (P3-ST 2084)”等参考预设后，系统按绝对亮度把PQ送到显示器，不再压缩（内容不超过显示器峰值时）。此时只有EyeQ的映射①生效：映射目标等于显示器峰值（如`--target-display-nits 1000`）时，屏幕上的亮度就是EyeQ计算出的亮度。

**做主观质量评估、HDR效果判断、tone mapping评估时，应使用参考模式并指定映射目标。**

### 4.2 非参考模式：系统再映射一次

默认预设（如“Pro Display XDR (P3-1600 nits)”）下：

- PQ不按绝对亮度显示，而是随当前SDR亮度相对放大或缩小；
- 超过当前EDR余量的高光，由系统再压缩一次；
- 系统的映射曲线未公开，会随亮度滑块、自动亮度和环境光变化，并参考EyeQ交给它的母版峰值（第4.3节）。

因此绝对亮度判断不可信，暗部和高光的可见程度也和实际观看条件不同。但同一时刻所有视频经过同一条系统映射，**A/B相对比较仍然公平**。输出PQ而显示器不在参考模式时，EyeQ启动时会给出警告。

### 4.3 交给macOS的HDR元数据

输出PQ时，EyeQ随窗口把一份HDR静态元数据交给系统。它只是元数据，不改动像素：

| 数值 | 内容 |
|---|---|
| 母版峰值（声明峰值） | 有映射目标N时：min(N, 所有HDR源母版峰值的最大值)；没有映射目标时：所有HDR源母版峰值的最大值 |
| MaxCLL、MaxFALL | 主视频的值，原样转交 |

- 声明峰值在开头几帧计算一次，之后固定，切换主视频不改变它。
- 非参考模式下，**声明峰值越高，画面整体越暗**，包括暗部和中间调，不只是高光。MaxCLL没有这种影响。
- 参考模式、DeckLink监视器、Ctrl+E保存的帧都不受声明峰值影响。
- 由此可知：不指定映射目标而同时播放多个视频时，母版峰值较低的视频会比单独播放时暗；指定映射目标时，声明峰值不超过目标，系统不会按源的更高峰值重复压缩。

### 4.4 与QuickTime对比

QuickTime不自己压缩HDR10，而是把源元数据交给系统映射。EyeQ不指定映射目标时做法相同，两者送屏像素相差1%以内，剩下的差别推测来自解码实现（如色度上采样）。指定映射目标后，母版峰值高于目标的视频会与QuickTime不同，因为高光由EyeQ先压缩。

肉眼对比两个播放器时注意：QuickTime失去前台时会压暗HDR高光，EyeQ不会。被观看的那一个必须在前台。

## 5. Ctrl+E保存的帧

Ctrl+E保存的是EyeQ呈现到桌面窗口的最终画面，即映射①之后、交给macOS之前的结果，不包含系统映射②：

- 分辨率是窗口的像素尺寸，不是视频分辨率；包含当前显示模式的布局（Slide分割线、Grid网格、黑边）和OSD文字。
- 按窗口当前的输出编码保存：PQ/BT.2020或SDR。
- 不指定映射目标时，保存的帧没有经过压缩，亮度可达源的峰值。
- 非参考模式下，保存的帧和屏幕上看到的亮度不同；参考模式下两者一致。

回看保存的DPX时，FFmpeg读不出文件头里的PQ/HLG和峰值（第6节），需要`setparams`加`--default-mastering-nits`。峰值填保存时的输出峰值：指定过映射目标时为该值，否则为源的母版峰值。

## 6. 源的母版峰值

EyeQ的映射①和声明峰值都依赖源的母版峰值。缺少母版峰值的PQ源会被当作最高10000 nits：指定映射目标时被过度压缩，不指定时声明峰值过高，两种情况画面都偏暗。EyeQ会对这样的源告警。

`--default-mastering-nits N`给缺少母版峰值的HDR源补上峰值：

- 只补缺失的源，已有母版峰值的源不改动。Dolby Vision没有mastering元数据时会从RPU取得峰值，不算缺失。
- MaxCLL和动态元数据不改动。MaxCLL高于N时只告警。

EyeQ通过FFmpeg读取元数据。HEVC、AV1等视频码流和MP4/MOV/MKV容器中的峰值都能读到；但DPX、JPEG XL即使文件里记录了峰值，FFmpeg也不读取，DPX的PQ/HLG标签同样读不出。`setparams`滤镜只能修改色彩标签，不能补充峰值，所以这类文件需要`setparams`和`--default-mastering-nits`一起使用。

## 7. DeckLink监视器

使用`--monitor-device`时：

- 必须指定映射目标。`--target-display-nits N`输出PQ信号，N应设为监视器的实际峰值；`--target-display-nits sdr`输出BT.709 / BT.1886信号，SDR白为`--reference-white`。
- PQ信号只声明PQ与BT.2020，不附带母版和MaxCLL元数据。
- 没有macOS的系统映射。监视器如何显示由监视器决定：参考监视器按绝对亮度显示，超出峰值会截断；`--tone-mapping clip`或`clip-rgb`可以让EyeQ按同样的方式处理。
- 桌面窗口和监视器使用同一份映射结果，显示同一画面（缩放、平移、滑动、切换都同步）。公共结果尺寸与监看模式不同时，按`--scale-method`等比缩放并加黑边。但桌面窗口仍会经过第4节的系统映射，两者看起来可能不同；以监视器为准。

## 8. 动态元数据的源

动态元数据按场景或逐帧描述亮度，用于把内容适配到不同亮度的显示器。它是否改变画面取决于标准和实现：有的方案只在目标比母版暗时压缩；有的方案（如HDR Vivid曲线、Dolby的显示管理）会根据目标调整整条曲线，目标更亮时也可能改变画面。

不指定映射目标时，EyeQ不映射，动态元数据不起作用。

- **Dolby Vision**：EyeQ完成重塑（reshape），并用L1场景亮度代替母版峰值，映射方式仍由`--tone-mapping`决定。EyeQ不实现Dolby官方的完整显示管理；QuickTime使用macOS的Dolby显示管理。**因此Dolby Vision在EyeQ和QuickTime中本来就可能不一致**，不指定映射目标也不能消除这个差异。
- **HDR10+**：EyeQ用场景峰值代替母版峰值，映射方式仍由`--tone-mapping`决定，不使用HDR10+自带的映射曲线。
- **HDR Vivid**：
  - 不加`--hdrvivid-render`时，按普通HDR10处理。
  - 加`--hdrvivid-render`时，必须指定映射目标，EyeQ按Vivid曲线映射到该目标，即使源峰值不超过目标也可能改变画面，不受`--tone-mapping`影响。这是对“目标显示器”的模拟：参考模式或DeckLink监视器下适合评估Vivid效果；非参考模式下系统还会再映射一次，不适合评估。

## 9. 多个视频

- 所有视频映射到**同一个**映射目标，在同一亮度空间内对比。
- 每个视频按**自己的**元数据映射。同一内容如果元数据不同（例如一个4000 nits母版、一个1000 nits母版），指定映射目标后画面会不同，这是元数据差异的真实结果。
- 系统映射只有一条，声明峰值只有一个，取自所有HDR源（第4.3节）。
- HDR和SDR视频一起对比：主视频为HDR时，SDR白按`--reference-white`放入HDR输出，非参考模式下它可能比桌面上的SDR白亮；主视频为SDR时，必须指定映射目标。
- 动态元数据只影响带有它的视频，与其他视频对比时，差异可能来自映射方式而不只是编码质量。做近无损对比时，建议让源峰值不超过映射目标，并且不开启`--hdrvivid-render`，使所有视频都不经过压缩。

## 10. 已知限制

- 参考模式下画面超过显示器峰值时，系统是截断还是压缩，尚未验证。
- SDR显示器上，“交给macOS映射”与“EyeQ映射到SDR”哪个效果更好，尚未对比。
- Dolby Vision、HDR10+尚未与QuickTime对比；`--hdrvivid-render`映射到`sdr`的效果尚未验证。
- Linux、Windows上不指定映射目标时由系统合成器处理HDR，效果未验证；第三方HDR显示器在macOS下的行为未测试。
